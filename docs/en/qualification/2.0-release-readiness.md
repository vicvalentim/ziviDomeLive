# ziviDomeLive 2.0.0 Release Readiness

This checklist validates the 2.0 native cubemap transition. Automated tests
verify API, metadata, packaging, and shader resource contracts; GPU visual
quality still requires target hardware.

For Contribution Manager packaging, metadata, and documentation requirements,
complete [Processing Publication](processing-publication.md) before this
hardware-facing checklist.

## Automated Evidence

- `./gradlew clean test build`
- `./gradlew qualificationTests`
- `./gradlew buildReleaseArtifacts`
- `python3 -m mkdocs build --strict`
- packaged `library.properties` with `prettyVersion=2.0.0` and Processing
  release counter `11`
- packaged `data/shaders/samplercube/*` resources
- no packaged `data/shaders/equirectangular.*` or `data/shaders/domemaster.*`
  six-texture shader passes

## Manual GPU Checks

Run `examples/CalibrationTool` on the target machine:

| Mode | +Z Front | +Y Top | Pitch | Yaw | Roll |
|---|---:|---:|---:|---:|---:|
| Standard | OK | N/A | OK | OK | OK |
| Skybox | OK | OK | OK | OK | OK |
| Equirectangular | OK | OK | OK | OK | OK |
| Domemaster | OK | OK | OK | OK | OK |

1. Select `SKYBOX` and confirm the original cubemap cross layout, face order,
   orientation, color bars, focus charts, and edge continuity.
2. Select `EQUIRECTANGULAR` and inspect longitude seam, poles, and horizontal
   orientation.
3. Select `DOMEMASTER` and inspect FOV, Size%, center sharpness, rim continuity,
   and blend-zone behavior.
4. Repeat at each output-resolution bucket that will be used in production.
5. Run `examples/InfiniteBackground`, use `E` to compare its real and synthetic
   sources, and verify Environment OFF/ON, intensity, and `yawOffset` in all four
   modes.
6. In Standard, drag through yaw and pitch, then change only orbit distance with
   the mouse wheel. Rotation must move the panorama; distance/translation must
   not. Foreground geometry must continue to occlude the far-depth Environment.
7. In Equirectangular, verify `+Z` Front, `+Y` Top, poles, Pitch/Yaw/Roll, and
   linear continuity across the magenta `-Z` longitude seam.
8. In Domemaster, verify `+Z` at center, rim continuity, poles, Pitch/Yaw/Roll,
   intensity, and `yawOffset`.
9. In Skybox, inspect every cross-face border and repeat at native size and a
   minified display size. This distinguishes base-level orientation/wrap issues
   from cubemap mipmapped filtering issues.
10. Repeat preview and enabled output independently, including every production
    resolution bucket, then validate NDI, Syphon, or Spout on real receivers.
11. Run `examples/SolarSystem` and orbit with the shared scene camera in Standard,
    Equirectangular, Domemaster, and Skybox. Geometry and Environment rotation must
    remain coherent; planet tracking and wheel distance must not introduce Environment
    translation or parallax. Confirm that spherical Pitch/Yaw/Roll still composes with
    the scene-camera quaternion in every spherical view.

Shader sampling and scoped OpenGL-state restoration require this GPU qualification;
headless tests cover longitude periodicity and direction math but cannot observe
driver texture fetches or samplerCube state.

No golden images are generated or inferred by the repository. Store qualified
captures, GPU/driver details, projector/lens notes, and receiver settings as
external release evidence.

## Known Runtime Note

Some Processing/OpenGL stacks can print `OpenGL error 1282 at top endDraw()` even
when rendering continues. Treat it as a driver/runtime diagnostic unless it is
paired with visible rendering failure or repeated resource loss.
