# Version 2.0.0

ziviDomeLive 2.0.0 promotes the spherical renderer to the native cubemap path.
The public scene drawing contract remains `Scene.sceneRender(PGraphicsOpenGL)`,
but the library no longer captures spherical content through six independent
Processing face targets.

## Highlights

- Spherical capture uses one reusable Processing scratch target and a GPU
  framebuffer blit to populate a native `GL_TEXTURE_CUBE_MAP`.
- Equirectangular, domemaster/fisheye, and skybox projections sample the native
  cubemap with `samplerCube` shaders.
- The legacy six-texture Processing shader passes were removed from the package.
- Domemaster/fisheye no longer depends on an intermediate equirectangular pass.
- The skybox layout preserves the original `CubemapView` cross matrix while
  sampling the native cubemap.
- LDR equirectangular environment backgrounds can be rendered by the library
  behind native cubemap capture, avoiding scene-owned sky spheres for spherical
  modes.
- Native cubemap logging is quieter: allocation/failure information remains,
  while per-face and per-frame success logs are suppressed.

## Migration Notes

Existing sketches that implement `Scene.sceneRender(PGraphicsOpenGL)` continue
to work. Scenes should still avoid `beginDraw()` and `endDraw()`; the library
owns target lifecycle, resolves the reusable scratch framebuffer, and copies
its final color into the native cubemap.

Direct renderer integrations should prefer the facade. Advanced callers that
previously consumed `PGraphicsOpenGL[]` cubemap faces must move to the native
`CubemapTarget` path.

## Validation

Use `examples/CalibrationTool` in `SKYBOX`, `EQUIRECTANGULAR`, and `DOMEMASTER`
views to validate face order, orientation, seams, color, and target hardware.
The OpenGL `1282` message can still appear on some Processing/driver stacks
without preventing rendering.
